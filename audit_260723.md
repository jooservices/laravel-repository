# JOOservices Laravel Repository Audit — 2026-07-23

## 1. Executive Summary

`JOOservices Laravel Repository` is a generic, trait-composed Eloquent repository package. It is not an application and correctly contains no controllers, FormRequests, services, jobs, domain models, REST endpoints, or third-party integrations. Their absence is therefore not an architectural finding.

The package has a coherent composition-first architecture and a strong local quality baseline: `composer ci` passed on PHP 8.5.8 with 185 tests, 470 assertions, and 99.75% line coverage. Three real findings remain:

| Priority | Finding |
| --- | --- |
| High | The release workflow claims a coverage gate but does not execute one. |
| Medium | A restrictive root field projection can silently break a `BelongsTo` eager load. |
| Low | CI executes mutable action tags and an unverified downloaded binary. |

No Critical issue, N+1 query defect, SQL-injection path, race condition, dead production code, logging defect, or SOLID violation was confirmed.

## 2. Architecture Review

The package appropriately uses trait composition rather than an oversized base repository. `EloquentRepository` owns model storage and lazy builder creation ([`src/Repositories/EloquentRepository.php:11`](/Users/vietvu/Sites/JOOservices/laravel-repository/src/Repositories/EloquentRepository.php:11)); traits separately own CRUD, filter, order, request-query, criteria, cache, iteration, cursor-pagination, and read behavior. The narrow contracts support interface segregation.

The Controller → FormRequest → Service → Repository → Model rules are application-layer rules and are not applicable to this reusable package. No architecture violation is confirmed.

## 3. Code Quality Review

Production files consistently declare strict types, use typed signatures, and keep behavior focused. The query lifecycle is explicit: terminal operations reset mutable query state using `try`/`finally` (for example, [`HasFilter.php:34`](/Users/vietvu/Sites/JOOservices/laravel-repository/src/Traits/HasFilter.php:34)).

### Medium — Field projection can silently break `BelongsTo` eager loads

**Evidence:** `HasRequestQuery::fromRequest()` applies `fields` before `with` ([`src/Traits/HasRequestQuery.php:80`](/Users/vietvu/Sites/JOOservices/laravel-repository/src/Traits/HasRequestQuery.php:80), [`:94`](/Users/vietvu/Sites/JOOservices/laravel-repository/src/Traits/HasRequestQuery.php:94)). `applyFieldClauses()` automatically retains only the root primary key ([`:188-215`](/Users/vietvu/Sites/JOOservices/laravel-repository/src/Traits/HasRequestQuery.php:188)). It does not retain root foreign keys. `PostStub::user()` is a `BelongsTo` relation using `user_id` ([`tests/Stubs/PostStub.php:21`](/Users/vietvu/Sites/JOOservices/laravel-repository/tests/Stubs/PostStub.php:21)). Selecting only `title` with `with: ['user']` omits `user_id`, leaving Eloquent unable to match the preloaded user to each post.

**Impact:** A valid combination of supported clauses can return models whose included relation is unexpectedly `null`, without raising an exception.

**Fix:** Resolve root eager-load relations before `select()` and automatically preserve the foreign key for root-level `BelongsTo` and morph-to relations. Alternatively reject unsafe `fields` + `with` combinations. Add an integration test using `PostStub` that selects `title` and includes `user`, in both permissive and strict allowlist modes.

## 8. Security Review

### Low — CI supply-chain integrity is not fully pinned or verified

**Evidence:** Workflows use mutable major/version tags, including `actions/checkout@v6.0.2`, `shivammathur/setup-php@v2`, `ramsey/composer-install@v4`, and `codecov/codecov-action@v7` ([`ci.yml:23-34`](/Users/vietvu/Sites/JOOservices/laravel-repository/.github/workflows/ci.yml:23), [`:153`](/Users/vietvu/Sites/JOOservices/laravel-repository/.github/workflows/ci.yml:153)). `secret-scanning.yml` downloads and installs a Gitleaks tarball with no checksum or signature verification ([`secret-scanning.yml:23-29`](/Users/vietvu/Sites/JOOservices/laravel-repository/.github/workflows/secret-scanning.yml:23)).

**Impact:** A compromised mutable action reference or release asset could execute with the workflow’s permissions. This is a hardening gap; it is not evidence of a compromise.

**Fix:** Pin all third-party actions to immutable full commit SHAs and keep those pins updated through Dependabot. Verify the Gitleaks checksum before extraction, or use a maintained SHA-pinned Gitleaks action.

No runtime network client, secret handling, raw SQL construction, or external API call exists in production code, so no further application security finding is substantiated.

## 9. Testing Review

`composer ci` passed locally with 185 tests and 470 assertions. Coverage was 96.15% of classes, 98.90% of methods, and 99.75% of executable lines. Unit tests cover all support classes and traits; the feature suite exercises package integration with Testbench and SQLite.

The missing boundary case is the `fields` + root `BelongsTo` eager-load combination described in section 3. Add the integration regression test before changing projection behavior. The high coverage figure does not cover this interaction, demonstrating why behavior-oriented integration coverage remains necessary.

### High — Release validation does not enforce its documented coverage threshold

**Evidence:** CI defines `COVERAGE_THRESHOLD: '90'` and explicitly parses `build/coverage/clover.xml`, failing below that value ([`ci.yml:13-15`](/Users/vietvu/Sites/JOOservices/laravel-repository/.github/workflows/ci.yml:13), [`:132-147`](/Users/vietvu/Sites/JOOservices/laravel-repository/.github/workflows/ci.yml:132)). The release workflow instead runs only `composer ci` ([`release.yml:52-53`](/Users/vietvu/Sites/JOOservices/laravel-repository/.github/workflows/release.yml:52)). `composer ci` runs linting and `test:coverage`, but contains no threshold assertion ([`composer.json:78-83`](/Users/vietvu/Sites/JOOservices/laravel-repository/composer.json:78)). Documentation nevertheless states that release runs a coverage gate ([`docs/04-development/ci-cd.md:26-31`](/Users/vietvu/Sites/JOOservices/laravel-repository/docs/04-development/ci-cd.md:26)).

**Impact:** A tagged release can pass despite statement coverage falling below the stated 90% quality policy.

**Fix:** Extract the Clover percentage check into a versioned repository script and run it from both CI and release, or repeat the CI threshold step in `release.yml`. Keep the 90% value in one source of truth and add a workflow-level regression check if practical.

## 13. Hidden Issues

- The projection/eager-load fault is silent: Eloquent returns the root records, but the requested relation cannot be associated because its foreign key was not selected.
- The release coverage policy can regress unnoticed because `composer ci` generates coverage without evaluating the configured threshold.

No other hidden bug, race condition, dead production code, N+1 query, or SQL-injection path was evidenced.

## 14. Recommended Refactors and Improvements

1. **Correctness:** preserve required root foreign keys when applying field projections with eager includes; add the regression coverage.
2. **Release quality:** centralize and invoke the existing 90% Clover threshold check from both CI and release validation.
3. **CI integrity:** SHA-pin actions and verify downloaded Gitleaks artifacts.
4. **Dependency hygiene:** when network access is available, run `composer audit --locked` as part of release readiness; this audit could not validate advisories because Packagist DNS was unavailable.
